YAMP Android — исправление пути выбора backup-файла

Изменены только:
app/src/main/assets/index.html
app/src/main/java/com/neyzo/yamp/MainActivity.kt

Что установлено:
Основная кнопка исходного ZIP вызывала NativeFiles.openBackupPicker(); имя
интерфейса совпадало с регистрацией в MainActivity. Доказать причину полного
отсутствия реакции именно в установленном APK по этому ZIP не удалось.
Подтверждён отдельный обход native-пути: восстановление из onboarding
напрямую нажимало скрытый input. Ошибка JS-моста основной кнопки также могла
незаметно переводить её на этот запасной путь. Это механизм возможного
отказа, а не воспроизведённая причина отказа на устройстве.

Внесённое изменение:
Обе точки восстановления используют одну кнопку. На android_asset кнопка
отправляет yamp-native://backup/import. WebViewClient перехватывает команду,
возвращает true и открывает ActivityResultContracts.OpenDocument. Команда
не загружается как страница; исходный file:///android_asset/index.html и
localStorage сохраняются. Вызов не зависит от доступности JavascriptInterface.
NativeFiles.openBackupPicker сохранён для совместимости и использует тот же
launcher. Launcher зарегистрирован до onCreate. Повторное открытие блокируется
до результата/отмены. Ошибка запуска выводится в Toast и Logcat YAMPBackup.
Picker показывает все типы файлов: MIME JSON у Android document providers
не всегда указан корректно. Содержимое проверяет прежний валидатор YAMP.
Activity Result читает файл с прежним лимитом 20 МБ и передаёт Base64 в
существующий yampNativeBackupBase64 → importBackupFile. При пересоздании
Activity результат ожидает готовности страницы. В браузере остаётся input.

Не изменены: формат backup, валидация, подтверждение, restore lock, rollback,
запись профиля и reload; Manifest, permissions, Gradle, workflows, музыка.
Полный index.html сохранён; файл не сокращён.

Проверено:
- синтаксис всех 22 inline-script блоков;
- изолированный click основной кнопки: Android-команда без JS interface;
- browser click: стандартный file input;
- побайтовая неизменность блока валидации/импорта/rollback;
- изменения исходников ограничены двумя перечисленными файлами.

Ограничение: Android SDK и устройство недоступны. APK не собран и запуск
системного picker на Android не подтверждён. Это исправленный альтернативный
путь, а не доказанное воспроизведение исходного отказа.

Проверка после сборки текущим workflow:
1. Установить APK обновлением, без удаления данных приложения.
2. Служебные инструменты → Восстановить из файла: должен сразу появиться
   системный выбор документа. Отменить и открыть повторно.
3. Повторить из знакомства. Проверить JSON из Downloads и облачного provider.
4. Корректный backup должен открыть прежнее подтверждение восстановления.
   После согласия — reload и восстановленный профиль.
5. Повреждённый JSON должен показать ошибку без изменения профиля.
6. Проверить сохранность прежних настроек и токена после обновления APK.
7. Если picker не появился, проверить фактически установленный новый APK;
   сохранить Logcat с тегом YAMPBackup и текст Toast. Не считать отсутствие
   Toast доказательством работоспособности.

Архив содержит проект целиком с исходной структурой и workflow.
